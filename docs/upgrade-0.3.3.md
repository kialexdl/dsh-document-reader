# 0.3.3：兼容范围下界调整为 DSH 0.2.0-rc.2

## 兼容声明

全部 10 项 DSH peerDependencies（宿主依赖版本约束）由精确的 `0.2.1-alpha.1` 改为 `>=0.2.0-rc.2 <0.3.0-0`，包含可选依赖。DSH 启动检查使用包含预发布版的范围匹配：

| 宿主版本 | 允许加载 |
|---|---|
| 0.1.7-rc.2、0.2.0-alpha.1、0.2.0-rc.1 | 否 |
| 0.2.0-rc.2、后续 0.2.0 候选版和正式版 | 是 |
| 0.2.1-alpha.1、后续 0.2 系列预发布版和正式版 | 是 |
| 0.3.0 的任何预发布版、正式版和更高版本 | 否 |

Cordis 宿主约束同步改为 `^4.0.4 || ^4.0.5-alpha.1`，接受 DSH 0.2.0-rc.2 自带的 Cordis 4.0.4，以及现有构建基线的 4.0.5-alpha.1。不能只放宽 DSH 而保留 Cordis 的精确约束。

## 可复现构建

DSH 开发依赖继续固定 `0.2.1-alpha.1`，Cordis 开发依赖固定 `4.0.5-alpha.1`。补齐原先仅通过 peerDependencies 自动安装的宿主包对应开发依赖，并同步生成锁文件，防止放宽声明后构建环境自动选择其他宿主版本。运行时由 DSH 提供这些宿主依赖，不将其打包到插件。

Schemastery 仍为 `3.18.5-alpha.1`，Zod、Python 依赖和所有业务源码保持不变。读取、搜索、模型选择、配置保存、指定图片优先解析、取消、审批以及持久缓存格式不变。

## 升级

1. 停止 DSH，保留现有插件配置与 Python 环境。
2. 解压同版本源码包，完整替换插件文件。
3. 在插件目录执行：

```powershell
pnpm install --frozen-lockfile
pnpm build
```

4. 重启实际使用的 DSH 配置档并刷新页面，确认插件版本为 `0.3.3`。原有安装路径不变时，无需重新添加插件。若配置档仍引用其他安装副本，则将新包添加到该配置档。

包含预构建 `lib` 的 `-github.zip` 同时交付源码和构建结果，可用于未来 GitHub 发布目录；纯源码 `-source.zip` 不含 `lib`。本次未执行 GitHub 发布。
