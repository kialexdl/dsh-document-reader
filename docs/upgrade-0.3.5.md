# 0.3.5：适配 DSH 0.2.1-rc.2

适配目标：2026-10-17 发布的 DSH 0.2.1-rc.2，源码提交 `687f282e8625c6b8d11ff58211a90524be2e4317`。

## 修改

- 增加 `engines.dsh`（宿主版本范围），保持 `>=0.2.0-rc.2 <0.3.0-0`。保留相同的宿主依赖范围供旧版 DSH 检查，不需要兼容性豁免。
- 将核心 DSH 开发依赖更新到 0.2.1-rc.2；本次安装时部分客户端与控制器包尚未发布该版本，固定使用 0.2.1-rc.1。锁文件记录实际版本，不将它们打包进插件。
- 更新 Cordis 4.0.5、Schemastery 3.18.5 和配套加载组件；保留原有 Python 文档解析依赖。
- 更新集成测试：使用新版客户端 Node.js 入口；加载网关所需的远程访问控制服务；为测试调用方提供身份、取消信号和交互类型；为模型目录测试提供仅测试用凭据，不调用外部模型。
- 配置页面增加说明：新版 DSH 会隐藏缺少有效凭据的模型。仍只允许选择明确声明图片输入能力的模型，不自动替换主会话模型。

## 升级

交付包包含纯源码压缩包和附带预构建产物的压缩包。二者均不包含依赖目录、Python 虚拟环境或密钥。

1. 在测试配置档中替换插件目录，保留原有插件配置与 Python 环境。
2. 源码方式执行 `pnpm install --frozen-lockfile`、`pnpm build`；已有预构建产物时无需重新编译。
3. 通过插件管理页重新加载插件。无法热重载时按 DSH 提示重启；更新后刷新页面，确认插件版本为 0.3.5。
4. 验证配置页的服务商和视觉模型，读取文档，并使用返回的图片定位参数测试同步读图。

GitHub 仓库同步包含源码与同版本预构建产物，可通过 DSH 插件页面使用仓库地址安装。

在 Linux、Node.js 24 环境执行构建、包完整性检查及真实 DSH 服务组合测试，包含模型目录、配置保存、工具加载/卸载、文档读取搜索、权限复查、缓存和同步读图。视觉调用使用确定性测试实现，不访问你的模型服务。未对 Windows 桌面版执行人工界面验收，也未逐个运行兼容范围内的历史版本。
