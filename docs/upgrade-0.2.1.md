# 0.2.1：图片模型选择修复

## 原因

`llm-pi-ai` 的 `input`（输入类型）接受 `text`（文字）和 `image`（图片）。适配器会将其转换为宿主模型服务的 `inputModalities`（支持的输入类型）。

DSH 0.1.7-rc.2 的 `session.modelCatalog()`（会话模型目录方法）只投影模型标识、名称、说明和推理选项，未保留输入能力；其远程接口结构也没有该字段。0.2.0 页面错误地把这个精简目录当作完整能力目录，从而过滤掉了图片模型。

此前页面测试手工构造了包含输入能力的目录，没有覆盖真正的宿主投影和传输边界，因此未发现该问题。

## 修复

- 新增插件只读模型目录，通过 DSH 实时注册表列出服务商，再解析每个模型的输入能力。
- 服务端和浏览器端共用包含输入能力的严格传输定义，使用 DSH 既有网关，不接管共享通信通道。
- 仍然只显示已确认支持图片的模型，不根据名称猜测能力，也不自动选择模型。
- 单个模型解析失败不会隐藏同服务商的其他有效模型；错误信息不包含密钥或端点响应。
- 实际视觉调用仍由 DSH 管理，并在调用前重新检查能力。Python 桥接和依赖未变化。

## 更新与选择

停止 DSH，将完整源码更新到原插件目录。在插件目录执行：

```powershell
pnpm install --frozen-lockfile
pnpm build
```

使用原来的命令重启 DSH，并刷新浏览器页面。插件安装路径未改变时无需重新添加插件；此次也无需重建 Python 环境。

对于本次反馈的配置，在插件配置页面选择：

- 服务商：`codeagent`
- 图片模型：`codeagent/Qwen3.6-27B-CodeAgent-VL`

原模型配置保留 `input: [text, image]` 即可，无需改成 `inputModalities`，也无需重复填写地址或密钥。保存后开启所需的图片说明/文字识别开关。

## 验证

构建成功，24 项 Node 测试全部通过，0 项跳过。新增测试使用实际 DSH 0.1.7-rc.2 的 `llm-pi-ai` 插件加载反馈中的七个模型配置：

1. 复现原生会话目录缺少图片能力字段、旧过滤逻辑返回空列表。
2. 经实际宿主网关、传输编码、浏览器网关，确认图片能力保留；物理传输使用进程内测试连接。
3. 页面组件使用上述真实调用结果，确认图片下拉框只有指定图片模型，并正确保存服务商和完整模型标识。
4. 验证模型能力未知、部分模型/服务商失败、取消和插件卸载。

测试未连接用户本机网关，不代表真实模型识别效果已验收。页面交互仍在模拟浏览器文档环境验证，未完成 Windows 浏览器现场验收。
