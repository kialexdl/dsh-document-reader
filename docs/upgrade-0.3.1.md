# 0.3.1：指定图片优先解析

在 0.3.0 大型 Word 两阶段优化上新增按需读图优先级，无需新增配置。

- 复制 `images[].read_args` 调用 `read_document`：目标尚未开始时移至高优先级队列；尚未进入当前搜索批次时直接加入；正在识别时等待并复用该任务；已完成时直接复用结果。
- 同一文档中，相同图片内容、相同识别模式仅执行一个任务。文字转录和语义说明是不同任务，但共用优先级队列与并发上限；按需说明优先于尚未开始的后台转录。
- 目标图片完成后立即结束本次等待，不等待其他图片或整个批次。超过 `progressive.waitMs` 时先返回待处理状态和保留 `image_id` 的 `next_read_args`，复制该参数继续读取。
- 指定 `image_id` 只提交这一图片，其他同块图片不会被连带提交。指定 `block_id` 时优先处理该块图片，仍按 `batchImages` 分批。
- 已经开始的图片不会被中断；它的切片继续完成后释放处理名额。高优先级任务依次使用空闲名额，随后继续原队列。持续提交高优先级请求会推迟后台进度。
- 原有权限、取消、超时、调用预算、结果大小、缓存和恢复规则仍适用。插队不绕过调用预算，也不额外增加并发。加入活动批次的请求沿用该批次的剩余超时和预算。

适用范围为启用渐进模式的 DOCX 文件。源码新增 `src/image-queue.ts`；`src/progressive.ts` 负责按图片复用任务、提交和等待。首轮正文提取仍需要完成后才能取得图片位置。

升级：完整替换源码，执行 `pnpm install --frozen-lockfile`、`pnpm build`，重启 DSH。Python 依赖和持久缓存格式未变，已有成功识别结果可继续使用。
